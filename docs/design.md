# Core Defender — 현재 구현과 향후 설계

환경: Minecraft 1.21.1 / NeoForge 21.1.262 / KubeJS 7 (2101.7.2) / EntityJS 1.5.2
기준: 2026-10-27, 0.1.5 계열 소스. 운영 명령과 기본 수치는 [현재 구현과 운영 안내](gameplay.md), 웨이브 구성은 `kubejs/config/coredefender-waves.json`을 참조한다.
공학 연계와 후반 콘텐츠는 장기 목표이며 현재 구현과 구분한다.

## 목표

전투 진행에는 공학이, 공학 진행에는 전투 파밍이 필요한 순환 구조.
멀티플레이 시 각자 원하는 콘텐츠를 하면서도 서로 연결된 느낌을 준다.

## 공간 구성

- **오버월드**: 채굴·탐험 + **메인 생산 시설**. 원자재 가공과 대부분의 공장은 여기에 둔다.
- **디펜스 차원** (서버 공유, 1개): 사각형 성벽으로 둘러싼 전선 기지. 성벽 안 자동화는 탄약 등 **일부 전선 자원에 한해** 플레이어가 구성한다.
- **차원 간 운반**: 현재 송신기(디펜스 밖) → 공용 54스택 버퍼 → 수신기(디펜스 안)의 아이템 전송을 구현했다. 각 장치는 9칸이며 10틱당 4/16/64/256개를 처리한다.
  유체 전송·Create 동력/IE 전력 연계 및 후반 AE2/Mekanism 연계는 향후 설계다.

## 성벽

- 사각형 에너지 장벽. 코어만 실제 블록이며, 장벽은 경계 데이터·구간별 HP와 클라이언트 렌더링으로 구성한다.
- 높이 (초기 5블록)와 구간 ID는 유지한다. 장벽 경계는 청크 영역에 정확히 맞추며 초기 크기는 32×32칸이다. 구 성벽 두께는 이전 처리에만 사용한다.
- 웨이브 적은 경계를 통과하지 못하며, 플레이어와 아군 투사체는 통과한다. 상단/하단은 닫지 않는다.
- 적 투사체는 경로와 장벽의 교차를 검사해 해당 구간에 피해를 주고 소멸한다. 적 폭발은 거리 기반 피해를 주고 장벽 너머 대상은 보호한다.
- **성벽 구간 하나라도 붕괴하면 패배.**
- 수복 수단 제공 (코어에서 자원 소모로 HP 회복 등).
- 처음엔 작고, **성벽 확장 설계도**를 코어에서 사용하면 장벽 경계가 사방 1청크씩 확장된다. 일반 시설은 유지하고 내부로 편입된 킬존 장애물은 회수한다.
  현재 설계도 레시피는 종이·석재 벽돌·지도이며, 웨이브 드롭과 공학 단계 재료를 요구하도록 바꾸는 것은 향후 설계다.
- 성벽 강화는 N/E/S/W 면별 최대 HP 업그레이드다. 구간별 HP는 독립 관리하며, 별도 성벽 방어력 강화는 아직 없다.
- 피해 누적은 구간 색상으로 표시하고, 피격 시 짧은 발광·스파크·피해 숫자를 표시한다. HP 75% 미만부터 표면에 균열이 생기고 손상이 커질수록 틈과 빠진 조각이 늘어난다. 면을 겹쳐 그리지 않으며 수복 시
  복원된다.
- 근접 공격은 몸체 가장자리에서 장벽까지 0.65블록 이내일 때 수행한다. 이동 충돌과 공격 쿨다운은 별개다.
- 경로/공격 판단은 4틱 간격으로 유지한다. 경로가 완료된 마지막 2블록 이내 접근에 한해 이동 명령을 매 틱 유지해 전진/정지 반복을 방지한다.
- 구 월드는 최초 로드 시 성벽 블록만 제거하고 위 시설을 코어 창고에 회수한다. 기존 강화·크기·HP는 유지한다.
- 장벽 위에는 설 수 없으며, 포탑과 사격대는 내부 지면에 설치한다. 게임 내 성능·멀티플레이·CBC 호환 검증은 별도로 필요하다.

## 코어 (관리 거점)

- 성 중앙에 위치, **무적** — 공격 대상이 아니다. 승패는 성벽으로만 결정.
- 우클릭 시 관리 화면: 자동 웨이브 활성화, 난이도 상승, 성벽 강화·수복·확장, 상태 확인.
- K 키 메뉴도 같은 화면을 열어 모든 조작 가능.

## 건설 규칙

- **성벽 안**: 자유 건설 (포탑, CBC, 탄약 자동화 등). 메인 생산은 오버월드 전제라 내부 공간은 방어·보급 위주로 설계.
- **성벽 밖**: 기본 건설 금지. 전용 아이템으로만 킬존 장애물 (블록 엔티티)을 설치할 수 있다.
    - 일반 몹은 장애물을 무시하고 우회한다. 단, 성벽까지 가는 길이 완전히 막히면 길을 막은 장애물을 공격한다.
    - 특정 몹 (파괴자 계열)은 장애물을 우선 공격한다.
- Schematicannon 처럼 이벤트 없이 블록을 놓는 장치에 대한 처리가 필요하다.

## 웨이브

- 최초 `/cd start`로 자동 진행을 활성화한다. 첫 전투와 클리어 후 대기는 기본 10분이며 시작 1분 전 전체 플레이어에게 알린다. 빠른 시작 보상 배율은 폐지했으며 현재 배율은 1이다.
- 1-1~1-10, 2-1~2-10의 두 난이도를 구현했다. 10웨이브 이후 일반 적 구성은 고정하고 반복 5회마다 미니 보스, 10회마다 보스를 추가한다.
- 1-10 클리어 후 성벽이 온전하고 전투 중이 아닐 때 기지에서 명령 또는 메뉴로 2단계에 진입한다. 2단계 이후 승급은 없다.
- 스폰은 네 성벽 면의 길이에 균등하게 배정한 위치에서 수직 바깥쪽으로 떨어진 곳이다. 원형 띠와 고정 스폰 지점은 사용하지 않는다. 기본 거리는 성벽 크기에 따라 64~128블록이며 지형과 위치 유효성의 영향을 받는다.
- 일반 적은 1단계 120~480마리, 2단계 560~1,000마리이며 소규모 배치로 계속 유입된다. 기본 동시 생존 상한은 최대 256마리다.
- 5웨이브는 강화 변명자, 1-10은 소환사, 2-10은 강화 피글린 야수다. 보스는 일반 적 소환 완료 후 생존 일반 적 비율이 20% 이하일 때 등장한다.
- 소환사만 90%에서 60초 동안 소진되는 피해 감소 방호를 받는다. 우민·파괴수를 추가 소환하며 보스와 남은 소환수를 모두 처치해야 클리어한다.
- 패배하면 남은 적을 제거하고 번호를 유지하며 보상을 지급하지 않는다. 붕괴 알림 뒤 수복 안내를 출력한다. 붕괴 구간을 모두 복구한 후 새 준비 시간을 부여하며 확장 크기는 유지한다.
- 전원 로그아웃 시 준비 타이머를 정지한다. 다른 차원에 접속 중이어도 진행되며, 진행 중 서버 재시작 시 해당 전투를 정리하고 재도전을 준비한다.
- 관리자는 자동 시작 중지·재개와 즉시 시작을 별도로 제어한다. 설정 JSON은 검증 후 재적용하며 진행 중 전투에는 시작 시점 설정을 유지한다.

## 몹 AI

- 기본 타겟: 가장 가까운 성벽 구간.
- 이동: **플로우 필드** — 성벽에서 바깥으로 거리 지도를 한 번 계산, 몹은 거리가 줄어드는 방향으로 이동.
- 장벽으로 직접 접근 가능한 평지에서는 직선 접근을 사용하며, 장애물이 있으면 경로 지도를 사용한다. 목표에 분산 오프셋을 반복 적용해 모서리로 미는 처리는 없다.
  장애물 설치/파괴 시에만 재계산. 장애물 칸은 "지나갈 수 있지만 비용이 큰 칸"으로 두어, 길이 막히면 자연스럽게 장애물을 공격.
- 플레이어 어그로: 플레이어가 몹을 공격하면 반경 12블록 안의 몹 중 **플레이어에게 도달 가능한 몹만** 10초 동안 플레이어를 노린다. 추적 최대 거리는 24블록이다.
  시간 초과·거리 이탈 시 성벽으로 복귀. 플레이어만 바라보지 않도록 한다.
    - 근접 몹: 플레이어에게 걸어서 닿을 수 없으면 (예: 장벽 안쪽, 사격대 위) 계속 성벽을 노린다.
    - 원거리 몹: 사거리 + 시야가 닿으면 반격 → 장벽 안쪽이나 사격대도 완전한 안전지대가 아니다.
- 웨이브 몹끼리는 피해 없음, 투사체는 웨이브 몹을 통과.

## 성장 축

- **공학 축**: 방어 수단. 스테이지 진행과 맞물린다 (아래 표).
- **전투 축**: 플레이어 직접 전투. 공학 단계와 무관하게 언제든 선택 가능. 장비·스킬 (추후 마법 모드 포함)로 성장, 레벨링 없음.
- 두 축은 드롭으로 연결: 웨이브 드롭이 공학 해금 재료이자 전투 장비 재료.
- 드롭 분리는 향후 설계다. 현재 클리어 보상은 설정의 아이템을 접속 중인 모든 플레이어에게 지급한다. 포탑 처치/플레이어 처치별 전용 재료 분리는 아직 구현하지 않았다.

## 기초 포탑 (단계 1, 자체 제작)

- 초반 제작 포탑은 화살·투석·기름 3종이다. 화염 포탑은 등록과 기능을 유지하되 제작법은 제외했다.
- 포탑별 탄약·연료를 소비하며 기본 모듈 슬롯은 2개다. 제작 가능한 모듈은 10종 × I~III이며 중복 장착 효과를 합산한다.
- 상세 UI, 면별 자동화, 재고 상한, 분석기 범위 표시와 회수 시 자원·설정 보존을 지원한다.
- 기름은 성벽 안쪽에서 외곽 바닥에 쏟는다. 감지는 전방 부채꼴이며 실제 흐름은 부채꼴 제한 없이 낙차를 우선한다. 평지 기본 이동은 5칸이고 낙하 후 이동 거리를 다시 계산한다.
- 기본 수치와 제작법은 [현재 구현과 운영 안내](gameplay.md)와 코드를 기준으로 한다. 포탑 자체 레벨은 없으며 다음 티어 업그레이드는 향후 설계다.

## 마법 모드 (추후)

- 후보: Iron's Spells 'n Spellbooks. 전투 축의 스킬 역할.

## 구현 분담

- **동반 모드 (Java)**: 장벽 경계·충돌·HP, 코어 (관리 블록), 몹 AI (플로우 필드·타겟팅·어그로), 사방 스폰, 킬존 장애물, 성벽 확장, 차원 간 전송 블록, 관리 UI.
- **KubeJS / 데이터팩**: 자동 웨이브 진행·보상·메뉴·레시피. 웨이브 수치는 JSON의 `/cd admin config reload`로 적용하고, 서버 스크립트는 `/reload`, Java 변경은 재시작한다.

## 정리된 결정

- 최초 활성화는 플레이어가 선택하며, 활성화 후에는 타이머로 자동 시작한다. 관리자 즉시 시작 명령도 제공한다. 수동 시작만 허용하던 이전 결정은 대체되었다.
- Actually Additions 제거됨. AE2는 저장소 용도로 유지.
- 이전 KubeJS 프로토타입의 월드별 차원·코어 HP·고정 스폰 지점은 공유 디펜스 차원·장벽 HP·분산 스폰으로 대체했다. 메뉴 UI/브리지는 재사용한다.

## 구현 기준

화살/투석/기름 및 보존된 화염 포탑과 2슬롯 모듈, 면별 자동화, 자원 보존 회수, 상세 UI 및 분석기 표시를 구현했다.
기존 문서의 단일 기초 포탑 수치보다 `turret/TurretStats.java`와 [현재 구현과 운영 안내](gameplay.md)를 우선한다.
투석 사거리 모듈의 탄도 도달 보정과 II/III 제작법 및 난이도별 10단계 웨이브 구성을 구현했다.
현재 수치·제작법·조정 파일은 [현재 구현과 운영 안내](gameplay.md)와 실제 코드·설정을 기준으로 확인한다.
모든 포탑 피해 (물약 화살의 지연 효과 포함)는 넉백을 발생시키지 않는다.
